# Chapter 24 — No Longer Just a Snapshot

## The following week

The note from when `metrics-server` got installed is still sitting there, untouched: `kubectl top` only gives instant numbers, close the terminal and it's gone, no history, no alerts. This week the founder asks a question that sounds simple but you can't answer: "was `chat-api` ever close to running out of RAM last week?" No idea. Nothing kept around to check.

You look into installing "Prometheus" — a name skimmed past that very first night reading the README, three weeks ago. Straight to the homepage, and there's a list of YAML to apply: CRDs defining `ServiceMonitor`, `PrometheusRule`, a Deployment for the Prometheus server, one for Alertmanager, one for Grafana, separate RBAC for each, a ConfigMap already stuffed with dozens of dashboards... A rough count puts it past 40 files. Hand-writing each one, the way `postgres.yaml` or `redis.yaml` got written, isn't realistic — just keeping them in sync with every new release would be a full-time job on its own.

### Helm — not `kubectl`, but not a stranger either

More reading, and every guide starts with a command never typed before: `helm install`. `Helm` is a package manager for Kubernetes — bundles a whole cluster of complex YAML (called a "chart") into a single installable/removable/upgradable unit with one command, the same way `npm install` installs a package instead of hand-copying every `.js` file.

```bash
brew install helm
```

```
==> Installing helm
🍺  /opt/homebrew/Cellar/helm/3.16.1: 8 files, 55.4MB
```

Add a "repo" — where Helm knows to look for charts, exactly the way `npm` knows to look on a registry.

```bash
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update
```

```
"prometheus-community" has been added to your repositories
Update Complete. ⎈ Happy Helming!⎈
```

Install `kube-prometheus-stack` directly — a chart bundling Prometheus, Grafana, Alertmanager, and a few other metrics-collecting components, all pre-wired to work together out of the box.

```bash
helm install kube-prometheus-stack prometheus-community/kube-prometheus-stack \
  -n monitoring --create-namespace
```

```
NAME: kube-prometheus-stack
NAMESPACE: monitoring
STATUS: deployed
REVISION: 1
```

A brand new namespace, `monitoring`, kept entirely separate from `ai-workspace` — exactly where it belongs, since this is infrastructure for observing the whole cluster, not a part of AI Workspace itself.

```bash
kubectl get pods -n monitoring
```

```

kube-prometheus-stack-grafana-...                        3/3     Running   0          58s
kube-prometheus-stack-kube-state-metrics-...              1/1     Running   0          58s
```

Six Pods, all from exactly two `helm` commands. Not one line of YAML written by hand.

### Into Grafana, seeing exactly what `kubectl top` never could

```bash
kubectl port-forward svc/kube-prometheus-stack-grafana 3000:80 -n monitoring
```

Grab the default admin password, auto-generated by Helm and stored in a Secret.

```bash
kubectl get secret kube-prometheus-stack-grafana -n monitoring \
  -o jsonpath="{.data.admin-password}" | base64 -d
```

Open `localhost:3000`, log in, go to the built-in "Kubernetes / Compute Resources / Namespace (Pods)" dashboard, select the `ai-workspace` namespace. A chart shows up — CPU/memory lines for all three `chat-api` Pods stretching back several hours, not a single frozen number like `kubectl top` anymore. Scroll back to this morning, and there's a clear small spike right when yesterday's load test ran.

The exact question the founder asked this morning — answerable now, no guessing: pull the chart back to last week, look straight at the `MEMORY(bytes)` line, see that the highest peak never once touched the `limits.memory` set a while back.

You open the last note from last week, cross off one line.

```
still open: full observability over time ✓ Prometheus + Grafana
via Helm, real history, scrollable. Automatic alerts when
something breaks — Alertmanager came bundled with the same
stack, but no rules configured yet. Separate thing, not today.

still open: automated deploys, running somewhere other than
this laptop.
```

Two lines left, unchanged. But the first of those original three is now only half-open — real numbers, real history, just nobody automatically getting told when something's wrong yet. You close the laptop, knowing exactly what's next.
